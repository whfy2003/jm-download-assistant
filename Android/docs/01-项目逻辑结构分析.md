# 原项目逻辑结构分析（jm-download-assistant）

> 分析对象：`jm-download-assistant-main/`（MIT，作者 whfy2003），下载能力来自上游
> [JMComic-Crawler-Python](https://github.com/hect0x7/JMComic-Crawler-Python)（MIT，hect0x7）。
> 本文只做结构梳理，为 Android 移植提供依据。

---

## 一、整体分层

```
┌─────────────────────────────────────────────────────────────┐
│ L4 分发层   installer.py（安装向导 / 写注册表 / 建快捷方式）      │  ← Windows 专有
│            launcher.py（首次运行向导 / 启动服务 / 卸载）         │  ← Windows 专有
├─────────────────────────────────────────────────────────────┤
│ L3 表现层   templates/index.html（三视图骨架）                  │
│            static/app.js（轮询 / 渲染 / 交互，约 600 行）        │
│            static/style.css（设计令牌：品牌色 #5b5bd6、深色主题）  │
├─────────────────────────────────────────────────────────────┤
│ L2 应用层   app.py（Flask，662 行）                            │
│            ├─ 目录与设置（settings.json、目录迁移、磁盘统计）      │
│            ├─ 记录层（日志解析 / 合并 / 写入 / 抹除）             │
│            ├─ 任务层（单任务状态机 + 线程 + 日志捕获）             │
│            └─ 文件层（打开 / 收藏复制 / 删除）                    │
├─────────────────────────────────────────────────────────────┤
│ L1 能力层   jmcomic（上游）：域名、接口加解密、拆图还原、并发下载    │
│            img2pdf 插件：整本合并 PDF、删原图                    │
│            curl_cffi：TLS 指纹伪装（Cloudflare 绕过）            │
└─────────────────────────────────────────────────────────────┘
```

**一句话概括**：本项目 = 一个「单任务的下载编排器」+ 一份「纯文本记录账本」+ 一套「三视图界面」，
真正的网络与图像能力全部委托给上游 `jmcomic`。

## 二、L2 应用层的关键逻辑（这是移植的核心）

### 2.1 路径与配置

| 项 | 源码运行 | 打包运行 |
| --- | --- | --- |
| 数据目录 `APP_DIR` | 项目根 | exe 所在目录 |
| 资源目录 `RES_DIR` | `webui/` | `_MEIPASS/webui` |
| 设置文件 | `<APP_DIR>/settings.json` | 同左 |
| 下载目录 / 收藏目录 | 设置项，可迁移 | 默认在 `APP_DIR` 下的「漫画」「收藏」 |
| 图片工作区 | `<APP_DIR>/downloads` | 同左 |

`settings.json` 就两个键：

```json
{ "pdf_dir": "E:\\漫画\\JM", "fav_dir": "E:\\收藏" }
```

### 2.2 记录账本（两个目录各一份，格式完全一致）

```
350234 | 董卓 上+下 | 2026-10-13 22:41:46      ← 标题行
350234 | 董卓 上+下.pdf | 2026-10-13 22:41:46  ← 文件行（同一时间戳）
```

读取时的三条规定（`_parse_records`）：

1. 按 `(编号, 时间)` 分组 → 一个本子两行合并成一条；
2. 组内优先取 `.pdf` 结尾的行作为真实文件名，去掉后缀作为显示标题；
3. 同一文件名出现多次，只保留时间最新的一条；最终按时间倒序。

写入（`_append_record_pair`）必须**两行共用同一时间戳**，否则界面会拆成两条。
删除（`_remove_log_entries`）按 `(编号, 文件名或标题)` 同时抹掉两行。

收藏夹还有一条「自愈」逻辑（`_sync_fav_directory`）：目录里有 PDF 但日志里没有的，
首次打开收藏页时自动补登记，编号写 `-`，时间取文件 mtime。

### 2.3 单任务状态机

```
        start_download(编号)
空闲 ───────────────────────► 运行中 ──成功──► 已完成(ok=true)
 ▲                              │
 └──────── 失败(ok=false) ◄──────┘
```

* 全局只有一份 `_state`（running / album_id / title / message / ok / started_at / finished_at / logs）；
* `threading.Lock` 保护，`/api/download` 发现 `running` 直接返回 409；
* 运行日志：`_TeeStream` 劫持 stdout/stderr + `_UiLogHandler` 挂到 `logging.getLogger('jmcomic')`，
  环形缓冲保留最近 200 行，前端每 1.5 s 轮询一次；
* 前端靠 `finished_at` 变化判断「刚刚结束」，只弹一次提示。

### 2.4 下载编排（`_run_download`）

```
记录下载前 PDF 集合 → 组装 option（把 pdf_dir 动态改成当前设置）
   → jmcomic.download_album(id, option)
   → 对比集合找出新生成的 PDF → 用文件名反推标题
   → 写两条记录 → 清理工作区空目录 → 更新状态
```

改成字符串注入 `pdf_dir` 的原因是：`option.yml` 是随包分发的只读资源，
而下载目录是用户可改的运行时状态，二者必须解耦。

### 2.5 目录迁移（`_relocate`）

* 逐项 `shutil.move`，目标已存在则跳过（不覆盖）；
* 旧目录空了以后 `os.rmdir`；
* 新旧目录互相包含 → 直接拒绝；
* 只允许绝对路径。

### 2.6 磁盘统计（三段色条的数据来源）

```
dir_size    ：递归累加该目录下所有文件大小
used/free   ：shutil.disk_usage(所在盘)
other_used  ：max(0, used - dir_size)     ← 同盘其它占用
```

前端把这三段按比例画成橙 / 紫 / 灰的条，20 秒缓存一次。

## 三、L3 表现层

单页三视图（`data-view` 切换，不换页）：

| 视图 | 主要元素 | 数据来源 |
| --- | --- | --- |
| 下载 | 编号输入、下载按钮、状态徽标、运行日志、搜索、记录列表 | `/api/state`、`/api/records` |
| 收藏 | 搜索、记录列表、告警条 | `/api/favorites` |
| 设置 | 两个目录路径、磁盘详情、保存并迁移 | `/api/settings`、`/api/disk` |

交互约定：**单击记录 → 用系统默认程序打开 PDF**；★ → 收藏 / 取消收藏；🗑 → 删文件 + 抹日志。
所有写操作都有 `confirm()` 二次确认——这一点在 Android 上要保留（改成 AlertDialog）。

## 四、HTTP 接口清单（Android 只需等价实现，不必保留 HTTP）

| 方法 | 路径 | 语义 |
| --- | --- | --- |
| GET | `/api/state` | 任务状态 + 最近日志 |
| POST | `/api/download` | `{id}` 启动下载 |
| GET | `/api/records` | `?q=&scope=recent|all` 下载记录 |
| GET | `/api/favorites` | 同上，收藏记录（先纳管目录） |
| GET/POST | `/api/settings` | 读 / 写目录（写时迁移） |
| GET | `/api/disk` | `?force=1` 磁盘三段数据 |
| POST | `/api/open-file` | `{file, scope}` 打开文件 |
| POST | `/api/open-folder` | `{scope}` 打开目录 |
| POST | `/api/delete` | `{file, id, scope}` 删文件 + 抹日志 |
| POST | `/api/favorite` | `{file, id}` 复制到收藏夹 + 写日志 |

## 五、与平台强绑定的部分（移植时必须替换）

| 原实现 | 用途 | Android 对应做法 |
| --- | --- | --- |
| `os.startfile(path)` | 用默认程序打开 PDF | `FileProvider` + `ACTION_VIEW`（`application/pdf`） |
| `os.startfile(dir)` | 打开目录 | 系统无「打开目录」通用语义 → 改为「导出到下载目录」 |
| `shutil.disk_usage()` | 磁盘总量 | `os.statvfs()`（Python 侧同样可用） |
| `winreg` / `WScript.Shell` | 安装、卸载、快捷方式 | 不需要（APK 安装包即分发形态） |
| `Flask` + 浏览器 | 界面 | 原生界面（本篇选型）+ Chaquopy 直接调用 |
| `curl_cffi` | TLS 指纹 | **必须替换**，见《方案与可行性》第二章 |
| `PyInstaller` | 打包 exe | Gradle + Chaquopy 打 APK |

## 六、必须保留 / 可以丢弃

**必须保留（业务价值所在）**

1. 记录账本的读写与合并算法（决定「历史记录」是否可信）；
2. 单任务状态机与运行日志（决定下载过程是否可观测）；
3. 收藏夹的自愈纳管（否则老用户的收藏会「消失」）；
4. 目录可迁移 + 磁盘三段统计（设置页的核心）；
5. 对 `jmcomic` 的调用方式（`download_album` + img2pdf 插件）。

**可以丢弃**

1. `installer.py` / `launcher.py` / `start-jm-web.cmd` / `stop-jm-web.cmd`：Android 不需要安装向导；
2. Flask 及全部 HTTP 路由（改为进程内直接调用 Python 函数，少一层端口与鉴权问题）；
3. `templates/` + `static/` 的 DOM 操作（改为原生视图，但**设计令牌与交互约定照搬**）；
4. `PyInstaller` 相关分支（`IS_FROZEN`、`_MEIPASS`）。

## 七、结论：移植的边界

移植不是「把 Flask 塞进 APK」，而是把 **L2 应用层拆成四个不依赖 Web 的模块**：

```
paths.py   目录/设置/迁移/磁盘
store.py   记录账本（解析/写入/抹除/纳管）
task.py    状态机 + 下载编排 + 日志捕获
net.py     传输层（顶替 curl_cffi）
```

界面只通过一层 JSON 接口（`api.py`）访问它们；
这样 Python 侧可以被桌面单测覆盖，Java 侧只负责展示与系统集成。
